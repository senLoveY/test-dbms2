# Тесты и состязания

Платформа для своих тестов: подготовка в соло и дуэль с другом (таймер, очки за скорость).

## Стек

- **Frontend:** React + Vite (деплой на Vercel)
- **API:** 3 Vercel Serverless Functions (`/api/rooms`, `/api/game`, `/api/quizzes`) — старые пути вроде `/api/rooms/create` проксируются rewrite'ами.
- **БД + Auth + Realtime:** Supabase

## Быстрый старт

### 1. Supabase

1. Создайте проект на [supabase.com](https://supabase.com) и скопируйте URL, `anon key` и `service_role key`.
2. Схема базы — это миграции в [`supabase/migrations/`](supabase/migrations), они применяются по порядку имён:

   ```bash
   npx supabase login        # один раз, откроет браузер
   npm run db:link           # привязать проект; спросит пароль базы (Settings → Database)
   npm run db:push           # применить все миграции, которых в базе ещё нет
   npm run db:status         # какие миграции применены
   ```

   Новая миграция: `npm run db:new имя` создаст файл в `supabase/migrations/` — пишите SQL туда,
   а не в SQL Editor. После пуша в `main` CI применит её сам (см. «Деплой»).
3. Если база уже была настроена вручную через SQL Editor (как рабочая), один раз выполните
   `npm run db:baseline` — он отмечает все существующие миграции применёнными, ничего не выполняя.
   Без этого `db:push` попытается накатить их заново.
4. В Dashboard включите **Authentication → Sign In / Providers → Anonymous sign-ins** (вход учеников в режиме «Класс»)
   и в **Authentication → Rate Limits** поднимите лимит анонимных входов: по умолчанию около 30 в час с одного IP,
   а в школе все телефоны выходят в интернет через один адрес.

### 2. Переменные окружения

Скопируйте `.env.example` в `.env`:

```bash
cp .env.example .env
```

Заполните:

- `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` — для фронтенда
- `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` — для API на Vercel
- `SUPABASE_JWT_SECRET` — *необязательно*. Если проект на старых HS256-ключах, API проверяет токен локально, без запроса в Supabase Auth. С новыми асимметричными ключами (Dashboard → Settings → JWT Keys) проверка и так локальная.
- `DEEPSEEK_API_KEY` — для генерации вопросов из текста (ключ с [platform.deepseek.com](https://platform.deepseek.com))

**Важно:** URL — только корень проекта (`https://xxx.supabase.co`), **без** `/rest/v1/`.

### 3. Локально

```bash
npm install
npm run dev          # только фронт (API нужен отдельно)
npx vercel dev       # фронт + API вместе (рекомендуется)
```

### Тесты

```bash
npm test             # node --test: очки, проверка ответов, модель теста, прогресс, доступ
```

CI (`.github/workflows/ci.yml`) на каждый push в `main` и в pull request прогоняет тесты и сборку.

### 4. Деплой на Vercel

1. Импортируйте репозиторий в [vercel.com](https://vercel.com).
2. Добавьте env-переменные из `.env.example` в **Project Settings → Environment Variables**.
3. Deploy.

Мониторинг ошибок: создайте проект в [Sentry](https://sentry.io) (тип «React», бесплатного плана хватает) и
добавьте его DSN в Vercel как `VITE_SENTRY_DSN` и `SENTRY_DSN` (одно и то же значение), затем передеплойте —
браузерный DSN подставляется при сборке. В Sentry уходят только ошибки: ошибки и падения страниц в браузере
(SDK грузится после отрисовки) и ответы 500 из API. Без email и id пользователя, без тела запроса и без
параметров адреса (коды комнат и т. п. вырезаются). Без DSN ничего не отправляется, а код Sentry не попадает в сборку.

Миграции базы применяет GitHub Actions (`.github/workflows/ci.yml`): после успешных тестов на пуше в `main`
выполняется `supabase db push`. Для этого в **GitHub → Settings → Secrets and variables → Actions** нужны
секреты `SUPABASE_ACCESS_TOKEN` ([токен аккаунта](https://supabase.com/dashboard/account/tokens)) и
`SUPABASE_DB_PASSWORD` (пароль базы). Без них шаг пропускается. Если в базе ещё нет истории миграций,
CI остановится и попросит один раз выполнить `npm run db:baseline`, а не станет накатывать всё заново.
Миграция и код деплоятся почти одновременно, поэтому изменения схемы делайте совместимыми с текущим кодом
(добавить колонку или функцию — да, переименовать или удалить используемое — отдельным шагом позже).

## Как пользоваться

1. Регистрация / вход.
2. **Кабинет** (`/me/quizzes`) — создать тест, сгенерировать из файла (PDF, DOCX, PPTX, TXT), по ссылке на статью или по теме без материала, добавить вопросы вручную или импортировать JSON.
3. **Опубликовать** тест.
4. **Соло** — подготовка со своей скоростью и разбором. Ответы сохраняются по каждому вопросу:
   на экране теста видно, что выучено (3 верных ответа подряд), а что нет, и кнопка «Повторить слабые места».
5. **Дуэль** — комната по коду, 2 игрока, таймер и очки. «Пригласить» открывает меню «Поделиться»,
   после игры — «Реванш» с теми же правилами.
6. **Поделиться тестом** — в «Мои тесты» → «Поделиться ссылкой» (тест должен быть опубликован).
   По ссылке `/q/:id` можно пройти тест, вызвать автора на дуэль или сохранить копию себе.
7. **Экзамен** — режим без подсказок с общим таймером (45 с на вопрос) и оценкой 5/4/3/2 в конце.
8. **Вызов по ссылке** — фиксированный набор вопросов, который друзья проходят когда удобно (по 30 с на вопрос,
   один раз). Сервер сам проверяет ответы и считает время; после финиша — рейтинг и сравнение по вопросам.
9. **Карточка результата** — картинка в стиле бланка для чатов и сторис после соло, экзамена, дуэли и вызова.
10. **Класс** — «Мои тесты» → «⋯» → «Играть в классе» (или формат «Класс» при создании комнаты).
   Вопросы показываются на проекторе, участники заходят по QR-коду или на `/play` с кодом комнаты,
   вводят имя и отвечают с телефона; аккаунт им не нужен, до 60 человек. На экране — сколько человек
   ответили, распределение ответов, топ-5 и пьедестал; результаты можно скачать в CSV.
   Пробел — следующий вопрос, P — пауза автоперехода. Гостевые аккаунты и комнаты класса удаляются через сутки.
   После игры — **отчёт урока** (`/me/reports`): процент верных по каждому вопросу, вопросы, которые стоит
   повторить (меньше 60% верных), самая частая ошибка и список участников. Отчёты хранятся полгода.
11. **Приложение на телефоне** — сайт можно установить на домашний экран (PWA); открытые ранее тесты
   доступны для соло без сети.

Справочник правильных ответов доступен только автору теста.

## API (кратко)

### Тесты

- `GET /api/quizzes` — список своих тестов
- `POST /api/quizzes` — создать черновик
- `GET /api/quizzes/:id` — тест с вопросами (только автор)
- `PUT /api/quizzes/:id` — сохранить / опубликовать
- `DELETE /api/quizzes/:id` — удалить
- `POST /api/quizzes/:id/generate` — черновик вопросов из текста (DeepSeek). PDF, DOCX и TXT читаются в браузере, на сервер уходит только текст (до 30 000 символов)
- `POST /api/quizzes/:id/duplicate` — копия
- `GET|POST /api/quizzes/:id/attempt` — попытки соло

### Комнаты

Игровые действия возвращают новое состояние комнаты (`{ state }`), так что клиенту не нужен лишний запрос.

- `POST /api/rooms/create` — `{ quizId, settings, mode }`, `mode`: `duel` (по умолчанию) или `classroom`
- `POST /api/rooms/join` — `{ code, nickname }`; гость (анонимный вход) может войти только в комнату класса
- `POST /api/rooms/kick` — `{ roomId, userId }`, убрать участника (ведущий класса)
- `GET /api/rooms/state?roomId=` или `?code=` — состояние комнаты
- `POST /api/game/start` — старт (только хост)
- `POST /api/game/answer` — отправить ответ
- `POST /api/game/timeout` — истечение таймера
- `POST /api/game/advance` — `{ index }`, следующий вопрос (хост, после reveal)
- `POST /api/game/end` — досрочно завершить игру (хост); в классе так же закрывается лобби
- `POST /api/rooms/leave` — выйти из комнаты
- `POST /api/rooms/settings` — настройки лобби (хост)

Все запросы требуют `Authorization: Bearer <supabase_access_token>`.

При старте дуэли вопросы копируются в приватную таблицу `room_snapshots`, поэтому правки теста не ломают текущий матч, а правильные ответы недоступны игрокам через Realtime/REST.
